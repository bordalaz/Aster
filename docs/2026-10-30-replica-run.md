## Как докачать файлы

```
docker compose run --rm api python -m migrate all
```
Без `--no-files` `fetch` берёт свежие ссылки (живут ~2 ч) и качает только недостающие файлы; `verify` станет `OK`, когда `нет файлов 0`.

- **Таблиц 28, а не 27**, как в анализе: в базе есть служебные `AddDataToZIP` и `AddAdressToZIP` (кнопки ЗИП). Перенесены как есть.

- **Одно вложение — в нескольких записях**: 116 id вложений встречаются больше одного раза (91 — фото, скопированные из `AddDataToZIP` в `ЗИП APS`). Исправлено: уникальность по id вложения снята (миграция 0003), вложения пересобираются при каждой загрузке.
- **Мусорные поля перенесены**: «Оборудование 2…6», «ID_Оборудования copy», «ID_Оборудования copy 2» и др.
- **Два варианта «На калибровку»** (`selmEQpkJbU49QE4K` redBright, `sel7EaySvqnLOK7qO` pinkBright) оба сохранены в `app_field.options.choices`. Но API отдаёт значение ячейки по имени, поэтому у 4 записей со статусом «На калибровку» **неизвестно, какой из двух вариантов выбран**. Для копии один в один это не важно (текст тот же); для rollup Номенклатура.«На калибровку», который считает только первый вариант, — в 1б-2 сверка с `at_computed` покажет, какие записи к какому варианту относятся.
