# Защита сервера

Сервер — только в локальной сети, в интернет напрямую не выставлен (так DDoS снаружи до него не дойдёт;
доступ издалека — потом через VPN WireGuard, а не открытые порты).

## Что включено

- **Вход в Aster** — у каждого свой логин; права по ролям и таблицам (чтение / правка), финансовые поля —
  только допущенным; частые попытки входа блокируются по логину и адресу; сайт нельзя встроить в чужую страницу.
- **Брандмауэр (ufw)** — `ops/harden.sh`: входящие только из локальных сетей (192.168/16, 10/8, 172.16/12)
  и только на 22 (SSH; снаружи роутер пробрасывает 2222), 80/443 (веб, страница /trust), 5201 («Открыть снимок»).
  База (5432) и API (8000) слушают только сам ноутбук.
- **SSH — только по ключу**: пароль и вход root запрещены, 3 попытки на подключение
  (`/etc/ssh/sshd_config.d/00-aster-hardening.conf`).
- **Автообновления безопасности** Ubuntu — `unattended-upgrades`.
- **HTTPS** — свой центр сертификации Caddy, см. [https-local.md](https-local.md).

`ops/harden.sh` повторять безопасно; перед включением брандмауэра ставит страховку — через 3 мин он сам
выключится, если связь пропала (снять: `sudo systemctl stop aster-ufw-undo.timer`).

## sudo с паролем

На время установки был `sudo` без пароля (`/etc/sudoers.d/aster-setup`). Убрать — с проверкой пароля, чтобы
не остаться без доступа (файл удалится, только если пароль `aster-su` введён верно):

    ssh -t -p 2222 aster-su@192.168.1.57 "su -c true aster-su && sudo rm /etc/sudoers.d/aster-setup && echo убрано"

После этого `ops/deploy.sh` спрашивает пароль `sudo` — запускать через `ssh -t` (иначе пароль не спросить):

    ssh -t -p 2222 aster-su@192.168.1.57 "cd ~/aster && git pull && sh ops/deploy.sh"
