## Что пришлось повторить за Airtable (первый прогон формул: 82/93)

- **Числа как в JS:** `x/0` → Infinity, `0/0` и `YEAR(пусто)` → NaN, в строке `"NaN"`. NaN/Infinity, пришедшие из `at_computed` во вход формулы (`{"specialValue": …}`), — тоже числа.
- **`#ERROR!`:** `DATETIME_FORMAT` от пустого и дата из lookup с несколькими значениями дают ошибку на всю формулу, а не пустоту (`Договоры.Код_Договора`, `Спецификации ЗИП.ID_…`, `Ведомость ЗИП.Год/Месяц` у 2 записей с двумя датами).
- **Имена из поля-связи с `"`** в строке формулы Airtable пишет как CSV: `"Резистивиметр 4.75""_№_830"`. У lookup текстового поля так не делает (`Оборудование.ID_Оборудования`).
- **Lookup поля-связи:** API отдаёт id записей, формула видит первичные имена.
- `SET_LOCALE(…,'ru')` + `MMMM` → «Январь»; `GGGG` — ISO-год недели; `DATETIME_DIFF` — целые единицы, у месяцев неполный не считается; `0 = BLANK()` — истина.
- Rollup «последнее/первое значение» (Работы.Статус, Оборудование.Местонахождение, Работы.LWD) повторены буквально по формулам из анализа: `;` внутри значения тоже режет список. Совпали все три.
- Count с фильтром `isNoneOf` (Номенклатура.В работе); lookup вложений сравнивается по id вложения (url у Airtable временный).

## Ограничения (сознательно)

- **Сверка изолированная:** каждая формула считается от входов, как они лежат в базе (для вычисляемых входов — от значений Airtable). Пересчёт по цепочке после правки записи — задача приложения, этап 1в.
- `TODAY()` в Airtable пересчитывается каждый день: «Дней на балансе», «КПЗО», «Номер справки» совпадают только на дату снимка.
- Поддержаны ровно те функции и форматы дат, что есть в базе. Незнакомая функция — ошибка разбора, тихого нуля не будет.
- Имена из связи с запятой в базе не встречались. Берёт ли их Airtable в кавычки, не проверено (`ponytail:` в `formula.py`).
