## Первый прогон: 21 совпало, 50 расхождений — причины и правки

1. **Формат фильтров.** Airtable отдаёт `{"operator": "and", "operands": [{"operator": ">=", "operands": [fieldId, значение]}]}`, а не `conjunction/conditions`, как предполагал план. Движок фильтров не видел вообще. Операторы в базе: `=`, `>`, `>=`, `doesNotContain`. Значения: число, **id варианта** `sel…` (переводим в имя через `choices`), строка (сравниваем без учёта регистра), `{"mode": "exactDate", …}`.
2. **Поля условий бывают вычисляемыми.** «Год» — formula, значение берём из `at_computed`; `Дата` в ЗИП APS — lookup; `ID_Рейсы APS` — связь. Отдельный оператор «год даты» (`valueKind: year` из плана) не понадобился: фильтр всегда по formula-полю «Год».
3. **Источник — поле-связь** (Персонал.*, Оборудование.Все перемещения, Ремонты ССК-Т.Список ЗИП). Значение — первичные имена записей второго звена (первичное поле само бывает formula → `at_computed`).
4. **Элемент rollup — ячейка связанной записи.** ARRAYJOIN склеивает ячейки через `,` и оставляет пустые (`a,,b`, хвостовая `,`). Ячейка-связь пишется как `x, y` и считается в COUNTA одним элементом (Персонал.Всего рейсов: экипаж рейса — одна ячейка). Значения lookup внутри ячейки расплющиваются.
5. **Вид значений как в API:** Decimal → float, дата → `YYYY-MM-DD` (dateTime-источник `timeZone: utc` → дата по UTC). Ошибка в formula-источнике (`{"specialValue": "NaN"}`) делает SUM/MIN/MAX тоже ошибкой — так в Airtable (Оборудование.Дней в ремонте).

Тесты на мини-снимке под каждый случай — `api/tests/test_compute.py`.

## Ожидаемое расхождение: «На калибровку»

У статуса Оборудования два одноимённых варианта: `selmEQpkJbU49QE4K` (redBright) и `sel7EaySvqnLOK7qO` (pinkBright). rollup `Номенклатура.На калибровку` фильтрует по первому. В Airtable он равен 0 у всех 79 номенклатур, значит все 4 записи «На калибровку» стоят на **втором** варианте. API отдаёт ячейку по имени, поэтому у нас варианты не различаются, и мы считаем эти 4 записи (3 номенклатуры: 1, 1, 2).

Решить при переносе логики: либо rollup «На калибровку» в Airtable фактически сломан (всегда 0) и его надо чинить, считая оба варианта, либо слить два варианта в один.
