# Этап 2д — фильтры, сортировки и группировки видов из Airtable

Публичный API Airtable у вида отдаёт только колонки. Остальное снято из веб-клиента Airtable
под аккаунтом владельца (только чтение: `GET /v0.3/application/{base}/read` с данными одного вида,
поле `viewDatas[].filters / lastSortsApplied / groupLevels`) и сохранено в `data/snapshot/view_filters.json`:
`{id вида: {f: {c, f: [[поле, оператор, значение] | вложенная группа]}, s: [[поле, по возрастанию]], g: [[поле, порядок]]}}`.
Id вариантов select уже заменены названиями; id записей (`rec…`) заменяются названиями при загрузке.

- `migrate views` / `migrate load` читают файл, `convert_view` переводит в наш config:
  - операторы Airtable → наши; `isAnyOf`, `|` (имеет любое из) → `any_of`, `isNoneOf` → `none_of`;
  - вложенное И разворачивается; ИЛИ по одной колонке → `any_of` (для `=`) или `contains_any` (для `contains`);
  - незаполненные условия (значение пусто) отбрасываются — Airtable их тоже не применяет;
  - если хоть одно условие не переводится — фильтры вида не ставятся вовсе, причина печатается
    (частичный фильтр молча показал бы не те записи). На текущей базе таких нет.
- Новые условия `any_of`, `none_of`, `contains_any` со списком значений; в панели — через «;».
- Группировка до 3 уровней (`group` — список; строка — старый формат). `ponytail:` порядок групп всегда по возрастанию.
- Подсказка «Airtable не отдаёт фильтры» убрана — теперь неправда.
