# Этап 2а — роли и доступ (spec R1–R7, E1–E4)

**Почему первым в этапе 2:** сейчас правит любой вошедший (аудит: «не выкатывать наружу до этапа 2»); формы (R5: пользователь создаёт записи только через формы), история и виды опираются на права.

## Права (сервер, каждый запрос)

| Роль | Видит | Правит |
|---|---|---|
| superadmin, admin | всё | всё |
| storekeeper | нефинансовое | ЗИП APS, Ведомость ЗИП, Спецификации ЗИП |
| user | нефинансовое | ничего (создание — формами, этап 2б) |

- Финансовые: Договоры, СЧФ, СЧФ 23 счет, Подрядчики, Работы подрядчики. Служебные AddDataToZIP, AddAdressToZIP скрыты всем (R8).
- Группы — константы по названию таблицы (`ponytail:`; при переименовании таблиц — колонка в `app_table`).
- `/tables` — только видимые; `/fields`, `/records` невидимой — 404 (не раскрываем существование). `editable` в `/fields` = поле правится **и** у роли есть право. PATCH без права — 403 + запись в лог (E4).

## Пользователи (R2, R3, R6)

- `app_user`: `must_change_password`, `blocked`; суперадмин один — частичный уникальный индекс.
- `/api/users` (admin+): список; создание с временным паролем (`must_change_password`); правка роли/блокировки; сброс пароля (снова временный).
- Цель — суперадмин → 403 «Суперадмина изменить нельзя» (E1). Назначать/снимать админа и трогать админов — только суперадмин. Создать суперадмина через API нельзя (только CLI).
- Удаления нет — блокировка (сохраняет авторство в истории). Блокировка закрывает сессии.
- `POST /api/auth/password` {old, new ≥ 8}: снимает `must_change_password`. Пока флаг стоит — данные 403 «Смените пароль» (E3); `/me`, смена пароля, выход доступны.

## Офисная сеть (R7, E2)

- `OFFICE_NETS` (CIDR через запятую); по умолчанию — частные сети (10/8, 172.16/12, 192.168/16, 127/8, ::1).
- Вход и каждый запрос роли storekeeper/user вне сети → 403 «Вход вне офиса доступен только администраторам».
- Адрес — `request.client.host`. За обратным прокси (NAS, этап 3) нужен доверенный `X-Forwarded-For` — `ponytail:` в коде.

## Веб

- Экран смены пароля при `must_change_password` и по ссылке из шапки.
- Сетка/карточка уже уважают `editable` из `/fields`.
- Экран «Пользователи» для admin+: список, создать, роль, блок, сброс пароля.

## Проверка

pytest на каждое правило таблицы прав, E1–E4, офисную сеть; Vitest на экраны; ручная проверка в браузере под user/storekeeper/admin.
