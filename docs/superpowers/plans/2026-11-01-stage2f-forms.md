# Этап 2ж — формы ввода (spec R12, R5, R36/E6)

Источник: 11 форм Airtable, снятых из редактора форм веб-клиента (только чтение) в
`data/snapshot/forms_airtable.jsonl`: `{view, table, after, fields: [{id, req, lines}]}` — поля по порядку,
обязательность, подсказки (строки вида «(указываем дату завершения ремонта)»). Служебные формы
AddDataToZIP/AddAdressToZIP не переносятся; форма-дубль той же таблицы с тем же набором полей — тоже.

- `app_form` (таблица, название, сообщение после отправки, поля `[{col, required, help}]`) + `app_form_submit`
  (ключ отправки → запись): повторная отправка с тем же ключом возвращает ту же запись (E6).
- `python -m migrate forms` — перенос (повторно — обновление по airtable_id).
- API: `GET /api/forms`, `GET /api/forms/{id}`, `POST /api/forms/{id}/submit {key, values}`,
  `GET /api/tables/{id}/names` — названия записей для выбора связи.
- Права: форму видит и отправляет тот, кто видит её таблицу (R5: пользователь создаёт записи только формами;
  финансовые формы — тем, кто видит финансы). Поля только из формы; select — только из вариантов;
  связь — только на существующие записи видимой таблицы; обязательные — не пустые.
- Новая запись: `created_by`, история «создано» по каждому заполненному полю, связи — в таблицы пар
  (в конец списка у обеих сторон), пересчёт формул.
- Веб: экран «Формы» — список и заполнение; выбор связанных записей с поиском; после отправки — сообщение
  из Airtable и «Заполнить ещё».
- `ponytail:` условные поля Airtable (в «Ремонтах» — «Расход, л/с») показываются всегда: условие из редактора не снять.
- Вложения в формах — следующим PR (загрузка файлов, R27).
