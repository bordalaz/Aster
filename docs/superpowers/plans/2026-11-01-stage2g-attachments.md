# Этап 2з — вложения (spec R27, R28, R37)

- Файлы на диске под внутренним именем: перенесённые — `ATTACH_ROOT/files/<att…>` (ATTACH_ROOT по умолчанию
  `/data/snapshot`), загруженные — `ATTACH_ROOT/uploads/<uuid>`; люди видят и скачивают под исходным именем.
- Загрузка `POST /api/uploads?name=` сырым телом с `Content-Type: application/octet-stream` (новой зависимости
  python-multipart не нужно; с чужого сайта такой запрос без preflight не уйдёт), до 50 МБ потоком, обрывок удаляется.
  До привязки к записи файл видит только загрузивший.
- Привязка: из карточки (`POST/DELETE /api/tables/{t}/records/{r}/attachments`, право правки таблицы) и из формы
  (id загрузок в значении поля). История — списком имён файлов было → стало; версия записи сдвигается.
- Скачивание `GET /api/attachments/{id}`: видят те, кто видит таблицу и поле; `nosniff`, `CSP: sandbox`;
  `?inline=1` (предпросмотр) — только картинки и PDF, и только если они такие по содержимому (R37), иначе — как вложение.
- `ponytail:` предпросмотр docx/xlsx/csv и листание картинок (R28) — не сделаны: такие файлы скачиваются;
  карточка файла — имя и размер (без даты и автора). Файл, убранный из записи, остаётся на диске.
