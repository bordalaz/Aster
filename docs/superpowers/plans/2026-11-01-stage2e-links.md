# Этап 2е — связи (spec R11), только чтение

- `/records`: ссылочное поле → `[{id, name}]` в порядке Airtable (pos у поля-источника, rpos у обратного).
  Название — первичное поле связанной таблицы, хранимое или вычисляемое (формула). Lookup ссылок
  (движок отдаёт id `rec…`) — тоже `[{id, name}]`.
- Связанная таблица скрыта от роли (финансы для пользователя/кладовщика) → значение `None`, `link_table: None`.
- `/fields`: у ссылки `link_table` — наш id таблицы для перехода.
- Сетка: названия через запятую, сортировка и поиск — по названиям; фильтры работают по названиям
  (заработали 5 видов из Airtable с фильтром по ссылке).
- Карточка: связанные записи — кнопки; щелчок открывает связанную таблицу сразу с карточкой записи.
- `ponytail:` правка связей — не сейчас; понадобится формам (R12), там и делать (выбор записи из таблицы).
- `ponytail:` названия считаются на каждый запрос `/records` (~0,3 с на Оборудование после прогрева движка);
  кешировать вместе с вычисляемыми, если станет заметно.
