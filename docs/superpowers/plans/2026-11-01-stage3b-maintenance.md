# Этап 3б — регламент ТО (spec R16–R21, E7–E10)

- Правила — `app_maint_rule` (начальное наполнение — таблица R17, `app/maintenance_rules.py: SEED`):
  модуль (префикс наименования номенклатуры или «тип:Трубное»), что (ТО-уровень / дефектоскопия / калибровка),
  порог в часах и/или месяцах, события, от которых идёт отсчёт; ТО-1 «при поступлении на базу». Пороги правит админ
  на экране «Регламент».
- События из данных:
  - ТО — «Ремонты ССК-Т», «Наименование работ» = «ТО Уровень N»; просто «ТО» (ставят отдельным модулям по необходимости) в регламент уровней не входит и отсчёт не сбрасывает;
  - дефектоскопия — «Дефектоскопия», «Дефектоскопия от»; калибровка — `app_calibration`;
  - поступление на базу (R19) — «Перемещение», «Куда» — база: название содержит «база», «склад», «рем цех».
- Наработка (R16) — сумма «Циркуляция, час» рейсов «Закончен» после события-отсчёта (по дате начала рейса),
  у которых стоит «Обработан» (данные проверены); рейсы раньше первого обработанного (до появления отметки,
  сентябрь 2025) — все законченные.
- Списан, Оставлено в скважине, Брак, На возврат — без подсказок регламента. Статусы — только вручную (А2 отложено).
- Колонки Оборудования (вычисляемые, только чтение): «Нужное ТО» (R18а — уровень плашкой, причина в карточке),
  «Последнее ТО» (R21), «Дефектоскопия» (дата + осталось / просрочено по часам или дате, E10, цвет R20),
  «На дефектоскопию» (R18б: ≥ 300 ч на базе), «Калибровка» (R21: дата + пара + «+N»);
  труба на кусту ≥ 400 ч — светло-красная строка.
- Не в этом PR: однократная смена статуса на «На дефектоскопию» системой (А2), «Справка» (R29), сводка на почту.
